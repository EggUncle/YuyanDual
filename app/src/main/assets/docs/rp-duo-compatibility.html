RP Duo 适配与兼容说明

文档日期：2026-10-22。适配代码基线：0e3cee3。本说明随语燕 RP Duo 测试版 APK 一起提供，可离线阅读；本次更新新增文档和阅读入口，键盘输入逻辑沿用该基线。

基于 EggUncle/YuyanDual 的 rp-duo 分支，上游双屏项目为 Maditer/YuyanDual。本文记录当前实现与已有实机证据，不将代码中的保护措施等同于所有设备、应用都已验证。

一、使用方式与适用环境

已验证设备为 Retroid Pocket Duo，Android 16。采集时上屏为 display 0、1920 × 1080、369 dpi；下屏为 display 2、1280 × 960、320 dpi。旋转会改变宽高，代码不把上述分辨率或下屏 ID 写死。

在系统“跟随输入窗口”模式下，上屏输入框调用下屏全屏键盘；下屏输入框调用同屏普通键盘，为编辑区域保留空间。输入法设置中可调整键盘高度、主题和按键反馈。

当前验证配置为 Settings.System 中的 ime_fixed=0、ime_show_on_second=1。输入法读取固件设置决定显示方式，不会自行修改它们。修改固件键盘模式后，必要时切换到其他输入法再切回，重新打开输入框。

二、双屏选择与固件兼容

ImeService 从系统 IME 窗口的 decorView.display 取得承载屏幕。在“跟随输入窗口”模式中，这与本轮验证的编辑客户端屏幕一致；代码没有使用隐藏接口查询其他应用焦点。

只有 IME 承载屏为默认主屏、且 ime_fixed 不为 1 时，才尝试副屏全屏键盘。候选屏来自 DisplayManager 的 DISPLAY_CATEGORY_PRESENTATION，排除默认屏、无效屏、OFF 和 DOZE_SUSPEND 状态，再选择剩余屏中 ID 最小的一块。多外接屏下的选择尚未实测。

ime_fixed=1 时尊重固件分配，使用普通 IME 窗口，不再创建另一块屏幕上的全屏键盘：ime_show_on_second=0 固定主屏，等于 1 固定副屏。此时 IME 承载屏不再代表编辑器所在屏，不能用它判断应全屏还是同屏保留编辑区域。

副屏不可用，或创建 Presentation 窗口失败时，回退到系统分配的普通 IME，并按该屏的尺寸重新布局。这个回退已在代码中实现，副屏移除与窗口失败等异常路径尚未逐项实机注入验证。

三、输入焦点、占位与生命周期

下屏全屏键盘使用 KeyboardPresentation，窗口设置 FLAG_NOT_FOCUSABLE，接收触摸但不抢走原应用的输入焦点。候选选词、组合串、删除和编辑器动作仍经 ImeService 的原 InputConnection 提交。

使用副屏键盘时，主屏 IME 内容采用明确测量为零高的占位视图；主屏的内容与可见边界置于窗口底部，触摸区域清空，避免上屏残留键盘遮挡、误缩放或拦截点击。普通模式则依据实际键盘顶部报告占用区域。关闭 Android 的全屏提取编辑模式，不等同于关闭下屏全屏键盘。

屏幕 ID、宽高、密度和旋转共同决定是否重建键盘。监听屏幕添加、移除、状态与配置变化；切换前移除旧窗口，输入结束、窗口隐藏或服务销毁时清理副屏窗口及相关状态。相同路由且视图仍挂载时复用视图。

KeyboardManager 在视图更换时重新绑定并重建容器，候选刷新和窗口边距处理只作用于当前绑定视图，避免旧屏幕的布局对象继续更新新键盘。

四、尺寸、旋转与文字显示

布局使用实际键盘所在屏的 DisplayMetrics 和显示上下文。KeyboardGeometry 统一计算按键区、拼音组合区及候选区，扣除本窗口的导航栏和用户底部留白。普通键盘的高度预算最多占该屏高度的 75%；副屏全屏模式可使用整屏预算。

高度比例限制在 0.1–1，候选缩放限制在 0.1–3，非有限数值使用默认值；底部留白限制在屏幕高度的四分之一以内。高度和留白按主屏竖屏、副屏竖屏、副屏横屏、副屏全屏四类保存。副屏全屏的默认高度比例为 1，已有用户自定义值不会因此被清空。

拼音与候选字按所在屏的密度换算，预留字形上下边界；按键字号同时受键盘高度和宽度限制，避免下屏竖屏时文字过大、被裁切。下屏导航栏边距由下屏窗口自身读取，不借用上屏 IME 的边距。

五、手柄与软件键盘

RP Duo 的手柄可能被系统报告为非字母硬键盘。输入法允许这种情况下继续显示触屏键盘，针对 KEYBOARD_12KEY 的显示请求直接允许；真正的外接 QWERTY 键盘仍遵循 Android 原有显示策略。外接实体键盘行为未在本轮专项验证。

这是键盘显示兼容处理，不包含手柄按键映射、扳机死区修改或屏幕唤醒功能。

六、中文引擎与安装包身份

仓库附带的 arm64-v8a/libyuyanime.so 是预编译原生库。对当前二进制的静态核查发现，它在北京时间 2026-01-01 起会阻止不匹配包名的 Rime 启动，可能表现为键盘能显示但没有中文候选。

该库检查的包名为 com.yuyan.pinyin.online.release、com.yuyan.pinyin.offline.release、com.yuyan.pinyin.online.debug、com.yuyan.pinyin.offline.debug。来源 APK 采用兼容包名 com.yuyan.pinyin.online.debug。本次恢复后的 fork 使用 com.yuyan.pinyin.offline.debug（debug）及 com.yuyan.pinyin.offline.release（release），便于与设备上的来源 APK 并存。原生库保持不变，未修改设备日期或二进制校验；本次恢复后的功能验证单独记录。

namespace 仍为 com.yuyan.imemodule，FileProvider 随 applicationId 配置。测试版可与不同包名的 release 版并存；同包名的 debug 版不能作为另一款独立应用并存。覆盖更新还要求签名一致，否则应先核对安装来源，不直接卸载用户数据。

Rime 词库随 APK 提供，资源清单记录 26 项 rime/build 运行资源。词库部署完成后仍无法选择输入方案时，每进程提示一次初始化失败；这项错误提示不记录输入内容。

仓库顶层 LICENSE 为 GPL-3.0，不能据此推定附带的所有预编译库均有相同授权或完整源码。原生库来源与限制的详细核查见源码仓库 validation/engine-compatibility.md；本次没有引入新输入引擎。

七、已有实机验证与范围

以下结果来自 2026-10-22 的适配基线验证，主要使用本地测试应用，不代表对所有第三方应用的承诺：

  • 上屏输入时下屏全屏、下屏输入时同屏普通键盘，以及两屏往返后的路由恢复。
  • 上下屏 T9 输入 64426 生成“你好”候选并提交；QWERTY 输入 nihao 的候选与上屏提交。
  • 中文、数字的完成动作抵达编辑器；数字 123 提交；密码自动切英文并以遮蔽显示及长度核对。
  • 下屏旋转至 960 × 1280 后，最终字号修复版的布局、候选和上屏提交复验通过。
  • 连续 5 次收起重开；约 1 秒熄屏、唤醒解锁后再次点输入框恢复下屏全屏键盘。

构建与 4 项几何计算单元测试已通过。截图、路由及动作结果保存在源码仓库 validation/rp-duo-2026-10-22/README.md；测试应用位于 validation/probe，日常使用不依赖它。

待验证：更多第三方搜索、聊天及浏览器输入框，长期使用、长时间休眠，其他固件与设备，多外接屏及异常断屏恢复。旋转或切屏时可能重建输入视图，未提交的组合串不承诺跨重建保留。保留的双拼、手写、剪贴板等功能未在本轮逐项回归。

八、已知现象与恢复方法

更新安装后曾出现一次键盘空白，按返回键收起、再次点击输入框后恢复。此现象尚未宣称彻底修复。

密码英文输入沿用上游组合行为：第一次“完成”确认当前组合串，第二次才触发编辑器 Done。应以目标应用的实际反馈为准。

上屏输入却只看到下屏普通键盘时，先检查固件是否处于固定模式；恢复跟随模式后重新切换输入法。若有键盘但没有中文候选，先核对安装包身份、初始化提示与词库部署状态。

此分支已移除语音识别、录音授权与语音设置，空格短按及长按松手后均执行普通空格操作。
